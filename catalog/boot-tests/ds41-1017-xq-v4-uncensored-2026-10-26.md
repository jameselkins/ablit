# Boot test: ds41-1017-xq-v4-uncensored on Vast, 2026-10-26

The maintainer approved this test with a $5 cap, and it ran with `ablit up --backends vast --trust verified --untested --max-spend 5 --yes` on their own Vast account. Host IDs, offer IDs, prices and keys are left out.

## Machine

One RTX PRO 5000 with 48 GB of VRAM and 96 GB of RAM on a Vast verified host, with the Xolotl 961d390 image (`ghcr.io/jameselkins/ablit-xolotl@sha256:5d36c97c...fb69`). The card is a Blackwell card and runs the image's `sm_120a` build.

The host RAM is close to the entry's 90 GB floor. The card has twice the VRAM of the 24 GB floor, so the 24 GB floor is still untested. The container's locked-memory limit was 8 MiB, the bootstrap logged a warning, and the engine started anyway.

The profile was the one in the entry: a context of 131072 tokens, `--kv-fp4`, `--tier-batch-pcie 0.25`, a 60 GiB arena, a 4096 MiB conversation cache and the Q2_K draft model.

## Stage times

Times come from the bootstrap log and the run record, in UTC.

| Stage | Time |
|---|---|
| Rental created to bootstrap start (image pull and container start) | about 2.2 minutes |
| Checks, disk read test and download speed check | about 2 minutes, 2.3 Gbps measured |
| Download and verify 371.7 GB, with the weight join running alongside | about 20 minutes, 2.2 to 2.3 Gbps |
| Engram tables | read in place from the official 1017 shards, no extraction |
| Engine start, health check and ready | 44 seconds |

The run was ready about 25 minutes after the rental was created.

## Results

1. `/v1/models` reported the model with a context of 131072 tokens.
2. Decode: three answers of 512 tokens each, with thinking on, took 20, 18 and 17 seconds in the engine, which is 28.4, 32.9 and 36.3 tokens per second. Counted from the request to the last token through the SSH tunnel, they ran at 24.3, 26.5 and 28.3 tokens per second. The expert cache hit rate was 94.7 to 95.9 percent.
3. Prefill: a prompt of 20,554 tokens (ablit's own Python source) took 41.1 seconds to the first token, which is about 500 tokens per second. The engine reported 481 tokens per second for the prompt. Three later fresh prompts of about 20,500 tokens read at 606 to 689 tokens per second.
4. Follow-up turns with thinking on did not reuse the conversation. Each follow-up on the 20K prompt read the whole prompt again, in 30 to 35 seconds. DeepSeek's chat encoder drops the earlier turns' thinking from the history, so the new prompt differs from the saved one near its end.
5. Follow-up turns with thinking off (`chat_template_kwargs: {"enable_thinking": false}`) reused the conversation. Two follow-ups on the 20K prompt reused 20,574 and 20,614 tokens, read only 15 and 14 new tokens, and answered in 4.5 and 3.4 seconds.
6. `POST /v1/messages` with a `tools` array and the `x-api-key` header returned a `tool_use` block for `get_weather` with the input `{"city": "Paris"}` and `stop_reason: "tool_use"`, both with `stream: false` (8.8 seconds) and with `stream: true` (1.8 seconds, with `input_json_delta` events).
7. A request without the endpoint key got HTTP 401.
8. `ablit down` destroyed the machine and confirmed that billing stopped. ablit estimated the spend at $0.74, including $0.25 of transfer charges.
